# IDENTITY (Cohesion SQL)

Generates integer column values with a durable, noncycling start/increment progression.

> **Status:** Implemented for CREATE TABLE and ALTER TABLE ADD on a table with no live rows.

## Syntax

```syntaxsql
column_name integer_type GENERATED { ALWAYS | BY DEFAULT } AS IDENTITY
    [ ( identity_option [ identity_option ] ) ]
column_name integer_type IDENTITY [ ( seed , increment ) ]

<identity_option> ::= START [ WITH ] signed_integer
                    | INCREMENT [ BY ] signed_integer
```

START and INCREMENT may appear in either order, at most once each. Parenthesized options must
contain at least one option. The SQL Server spellings IDENTITY and IDENTITY(seed, increment)
mean ALWAYS. Identity, generated, start and increment remain contextual column names.

## Arguments

- **`integer_type`** — Built-in TINYINT, SMALLINT, INT/INTEGER or BIGINT; domains are excluded.
- **`START` / `seed`** — First generated value; defaults to 1 ascending or -1 descending.
- **`INCREMENT`** — A nonzero signed Int64 literal, default 1; negative values descend.
- **`ALWAYS` / `BY DEFAULT`** — Whether explicit assignments to the generated column are refused.

## Remarks

Only one identity column is allowed per table. It implies NOT NULL and excludes a DEFAULT
declaration. Identity does not itself declare a primary/unique key. START must fit the bounds for
the chosen direction; there is no cycling or custom MINVALUE/MAXVALUE.

| Type | Ascending range | Descending range |
| --- | --- | --- |
| TINYINT | 1 through 127 | -128 through -1 |
| SMALLINT | 1 through 32,767 | -32,768 through -1 |
| INT / INTEGER | 1 through 2,147,483,647 | -2,147,483,648 through -1 |
| BIGINT | 1 through 9,223,372,036,854,775,807 | -9,223,372,036,854,775,808 through -1 |

These are PostgreSQL's direction-dependent generator bounds, also applied to the SQL Server
lexical form. A positive start with a negative increment, or zero start ascending, is invalid.

Omitting the column, INSERT DEFAULT VALUES, or an explicit whole VALUES item DEFAULT generates
one value per row; INSERT SELECT can omit the destination identity column. ALWAYS rejects an
explicit INSERT value, including NULL, and every UPDATE assignment to that column, including
DEFAULT. Explicit DEFAULT in INSERT is allowed, and other columns can be updated normally.
BY DEFAULT accepts explicit non-null values without advancing the counter; UPDATE SET id = DEFAULT
allocates a new value. Explicit NULL fails NOT NULL (`COHSQLE024`, 23502). A generated collision
with an explicitly supplied key uses ordinary primary/unique enforcement. SQL has no MISSING.

Allocation durably reserves up to 32 values before returning any, independently of the data
transaction. Rollback, failed constraints and clean/crash restart can leave gaps; generated values
are never reused for that table identity and are not ordered by commit. Exhaustion fails the
whole statement without partial row writes, but consumed values remain consumed. DROP TABLE or
dropping the identity column retires its counter; a recreated table starts at START.

ADD COLUMN IDENTITY requires no live rows, checked under the DDL lock; deleted historical versions
do not prevent it. Full-definition ALTER COLUMN preserves an existing identity only with the same
type, NOT NULL and no DEFAULT. Changing generation options, type or nullability is refused.
Typed compiled schemas cannot represent identity metadata: provisioning refuses a typed schema-owned
identity table with SqlSchemaMigrationException / `COHSQLP005` and "Nothing was changed."
SQL script-created tables retain their SQL definitions.

[INFORMATION_SCHEMA.COLUMNS](../system-views/information-schema.md) exposes the definition and
directional bounds; COLUMN_DEFAULT is NULL. SQL storage format is 22, with catalog counter kind 16. Table extension 6 retains the identity
facets and adds frozen missing-value literals; identity counters remain independent of insert defaults.

## Diagnostics

| Code | Meaning and trigger | SQLSTATE where supplied |
| --- | --- | --- |
| `SQL0003` | Malformed/duplicate options, invalid signed Int64 literal, or explicit NULL combined with NOT NULL, PRIMARY KEY or IDENTITY in either order | — |
| `COHSQLE025` | Invalid identity type, second identity, zero increment, out-of-range start, DEFAULT conflict, prohibited assignment/ALTER, populated-table ADD or exhausted allocation | 428C9 (`generated_always`) for explicit ALWAYS assignments; other failures share the local code |
| `COHSQLE024` | BY DEFAULT identity receives explicit NULL | 23502 |
| `COHDBL001` | SERIAL/BIGSERIAL/SMALLSERIAL, CREATE SEQUENCE, OVERRIDING, custom bounds/cycle/cache, RESTART/SET GENERATED or generated stored expressions | — |

SQL and native user domains named serial, bigserial or smallserial are refused, including quoted
SQL names. SQL reports COHDBL001 suggesting GENERATED BY DEFAULT AS IDENTITY; the native
SqlType.CreateDomain API throws ArgumentException with the same direction.

## Examples

Execute each statement separately:

```sql
CREATE TABLE ids (id BIGINT GENERATED BY DEFAULT AS IDENTITY
    (START WITH 10 INCREMENT BY 3) PRIMARY KEY, label INT);
INSERT INTO ids (label) VALUES (1), (2);
INSERT INTO ids VALUES (DEFAULT, 3);
UPDATE ids SET id = DEFAULT WHERE label = 1;
SELECT id, label FROM ids ORDER BY label;
CREATE TABLE descending_ids (id SMALLINT GENERATED ALWAYS AS IDENTITY (INCREMENT BY -1));
INSERT INTO descending_ids DEFAULT VALUES;
INSERT INTO descending_ids VALUES (DEFAULT);
SELECT id FROM descending_ids ORDER BY id DESC;
CREATE TABLE lexical_ids (id INT IDENTITY(100, 5));
INSERT INTO lexical_ids DEFAULT VALUES;
SELECT id FROM lexical_ids;
```

The queries return `(19, 1)`, `(13, 2)`, `(16, 3)`; then `-1`, `-2`; then `100`.
`UPDATE lexical_ids SET id = DEFAULT` reports COHSQLE025. `CREATE TABLE bad (id INT NULL IDENTITY)`
reports SQL0003: `Conflicting NULL/NOT NULL declarations for column 'id'.`

Format 19 quotes PERCENT and TIES in persisted SQL. Format 20 adds persisted SET NULL,
SET DEFAULT and NO ACTION delete actions. Format 21 introduced namespace records of kind 15. Format 22 quotes STRING_AGG and LISTAGG
identifiers in persisted SQL. Every earlier format is refused at open; there is no
upgrade path. Compiled schema format remains version 7.
