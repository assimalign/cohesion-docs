# IDENTITY (Cohesion SQL)

Generates integer column values through an owned sequence.

> **Status:** Implemented, including ALTER identity, overrides and populated-table backfill.

## Syntax

```syntaxsql
column_name integer_type GENERATED { ALWAYS | BY DEFAULT } AS IDENTITY
    [ ( identity_option ...n ) ]
column_name integer_type IDENTITY [ ( seed , increment ) ]
column_name { SERIAL | BIGSERIAL | SMALLSERIAL | SERIAL2 | SERIAL4 | SERIAL8 }

identity_option := START [ WITH ] integer | INCREMENT [ BY ] integer
                 | MINVALUE integer | NO MINVALUE
                 | MAXVALUE integer | NO MAXVALUE
                 | CACHE integer | CYCLE | NO CYCLE

ALTER TABLE table_name ALTER [ COLUMN ] column_name
    { ADD GENERATED { ALWAYS | BY DEFAULT } AS IDENTITY [ ( identity_option ...n ) ]
    | SET GENERATED { ALWAYS | BY DEFAULT }
    | SET identity_option
    | RESTART [ [ WITH ] integer ]
    | DROP IDENTITY [ IF EXISTS ] }
```

Options may occur in any order, once each; empty parentheses are invalid. SET GENERATED,
sequence options (each preceded by SET) and RESTART may combine in one ALTER statement.
IDENTITY and IDENTITY(seed, increment) mean ALWAYS. Identity words remain contextual names.

## Definition and options

The type must be a built-in TINYINT, SMALLINT, INT/INTEGER or BIGINT; domains are excluded.
Only one identity is allowed per table. It implies NOT NULL and excludes a declared DEFAULT;
it does not imply a primary/unique key. Increment defaults to 1 and must be a nonzero signed
Int64. CACHE defaults to 1 and NO CYCLE is the default. The shared allocator still durably
reserves up to 32 values regardless of CACHE; CACHE is metadata, not a session cache.

| Type | Default ascending bounds | Default descending bounds |
| --- | --- | --- |
| TINYINT | 1 through 127 | -128 through -1 |
| SMALLINT | 1 through 32,767 | -32,768 through -1 |
| INT / INTEGER | 1 through 2,147,483,647 | -2,147,483,648 through -1 |
| BIGINT | 1 through 9,223,372,036,854,775,807 | -9,223,372,036,854,775,808 through -1 |

START defaults to the directional starting bound. Explicit MINVALUE/MAXVALUE can change these
bounds within the type's range; NO restores the directional default. Bounds must be ordered and
START must fit. CYCLE wraps at the directional bound and can repeat values. Noncycling
exhaustion is CS02002 (22003).

SERIAL/SERIAL4 mean INTEGER GENERATED BY DEFAULT AS IDENTITY; BIGSERIAL/SERIAL8 mean BIGINT;
SMALLSERIAL/SERIAL2 mean SMALLINT. This is a deliberate difference from PostgreSQL's sequence
and DEFAULT expansion. Serial names cannot be used for domain declarations, including quoted
names; generated stored expressions, SCOPE_IDENTITY and pg_get_serial_sequence remain excluded.

## Owned sequences

Each identity owns a sequence in its table's schema, named `table_column_seq`. Collisions use
numeric suffixes: `table_column_seq1`, then 2, and so on. Table/column renames preserve that
sequence name. Dropping the table, column or identity removes its owned sequence atomically;
external defaults depending on it must first be removed. DROP SEQUENCE refuses an identity
sequence even with CASCADE (CS03080). Its ownership cannot be changed with OWNED BY (CS03081).

[CREATE/ALTER SEQUENCE OWNED BY](../statements/create-sequence.md#ownership) can attach a
standalone sequence to a same-schema column; OWNED BY NONE detaches it. This ownership alone
does not make the column an identity. [Sequence defaults](default.md#sequence-defaults) track
dependencies separately under DROP RESTRICT/CASCADE.

[INFORMATION_SCHEMA.SEQUENCES](../system-views/information-schema.md#sequences) lists identity
sequences alongside standalone sequences, deliberately differing from PostgreSQL. Generated
names can therefore be discovered for currval. COLUMNS reports effective START, INCREMENT,
MINIMUM, MAXIMUM and CYCLE options; COLUMN_DEFAULT is NULL for an identity.

## Assignment and overrides

Omitting a column, INSERT DEFAULT VALUES or a whole VALUES item DEFAULT allocates a value.
INSERT SELECT may omit the destination identity column. SQL has NULL and no MISSING value.

| Policy | Supplied INSERT identity value |
| --- | --- |
| ALWAYS, no override | Refused, including NULL; DEFAULT still generates |
| BY DEFAULT, no override | Accepted without advancing the allocator; NULL fails NOT NULL |
| OVERRIDING SYSTEM VALUE | Permits explicit values for ALWAYS; BY DEFAULT keeps its normal behavior |
| OVERRIDING USER VALUE | Generates for either mode, replacing supplied identity values, including NULL |

Place the override after the INSERT column list and before VALUES/SELECT. MERGE places it
between the INSERT column list and VALUES. The policy applies to VALUES, INSERT SELECT,
ON CONFLICT proposals and MERGE INSERT actions. Conflicts can consume generated values even
when no row is inserted. UPDATE, ON CONFLICT UPDATE and MERGE UPDATE accept DEFAULT for
ALWAYS identities; other explicit assignments are refused. BY DEFAULT also accepts explicit
UPDATE values. Explicit values never advance the allocator; generated collisions use ordinary
primary/unique enforcement.

OVERRIDING USER still binds ignored inputs and validates assignment compatibility. Invalid types,
unknown functions and invalid string input conversions fail before identity allocation. VALUES
and MERGE INSERT also check immutable-call and signed-constant folding errors before discard:
`CAST('abc' AS INT)` fails CS02022 (22P02). Typed numeric casts and volatile inputs discarded in
those action lists remain unevaluated. INSERT SELECT sources materialize normally before defaults.

Every identity allocation updates this session's currval for its owned sequence and selects
lastval, including backfill. Explicit assignments do not. Values and observations survive rollback
and statement failures; reservations can leave gaps after rollback, constraint failure or reopen.
Allocation order is independent of data commit order. [DISCARD ALL](../statements/discard-all.md)
clears the session observations.

## ALTER and backfill

ADD GENERATED requires an existing NOT NULL column with no identity or default. It preserves
all stored values and does not generate replacements for them. SET GENERATED changes assignment
policy. SET START changes restart metadata without moving the cursor. Bare RESTART uses START;
RESTART WITH n sets the next value without changing START. DROP IDENTITY preserves values and
NOT NULL; IF EXISTS ignores an absent identity. Each ALTER self-commits and is refused inside
an explicit transaction (CS04003, 25001).

Adding a *new* identity column to a populated table backfills live rows in physical owner-page/slot
scan order. It copies storage and enforcing indexes before one atomic publication, so failure or
cancellation before publication leaves the old table intact. Backfill uses the shared allocator
and records the caller's currval/lastval. Retained conversion/chunk buffers share the statement
budget; exhaustion is CS05067 (53200). ADD GENERATED on an existing column is metadata-only.

Explicit [ALTER COLUMN TYPE](../statements/alter-table.md#alter-column-type) permits integer-family
changes, preserving the live last value and called flag, including pending RESTART/setval(false).
Full-definition identity type changes remain refused. Compiled typed schemas have no identity
metadata and retain version 9; SQL script-created tables retain their SQL definitions.

[TRUNCATE](../statements/truncate.md) CONTINUE IDENTITY preserves allocator state. RESTART IDENTITY
atomically restarts **all sequences owned by tables in the truncate closure** at configured START,
including ordinary OWNED BY sequences. Reopen still skips unused reserved values.

| CS03024 | Explicit NULL accepted by the generation policy violates NOT NULL | 23502 |
| CS02002 | Noncycling owned sequence exhausted | 22003 |
| CS03078 | ADD GENERATED requires an existing NOT NULL column | 55000 |
| CS03079 | ALTER operation requires an identity that is absent | 55000 |
| CS03080 | DROP targets an identity sequence, or RESTRICT encounters a column default dependency | 2BP01 |
| CS03081 | Invalid OWNED BY target or identity ownership change | 55000 |
| CS04067 | Identity incarnation disappeared, or a live referential default needs an unplanned sequence grant; retry/replan | 40001 |
| CS05067 | Backfill memory budget exhausted before publication | 53200 |
| CK00001 | Generated stored expressions, serial domain names or excluded identity helpers | — |

## Examples

Execute separately in one session in a fresh database:

```sql
CREATE TABLE ids(id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,k INT UNIQUE);
INSERT INTO ids OVERRIDING SYSTEM VALUE VALUES(20,1);
INSERT INTO ids OVERRIDING USER VALUE VALUES(99,2);
INSERT INTO ids OVERRIDING USER VALUE SELECT 100,3;
SELECT id,k FROM ids ORDER BY k;
SELECT currval('ids_id_seq'),lastval();
ALTER TABLE ids ALTER id RESTART WITH 10 SET GENERATED BY DEFAULT;
INSERT INTO ids(k) VALUES(4);
```

The SELECT results are `(20,1)`, `(1,2)`, `(2,3)`, then `(2,2)` as BIGINT observations.
The final insert generates id 10. In a separate fixture:

```sql
CREATE TABLE alter_ids(id INT NOT NULL);
INSERT INTO alter_ids VALUES(8);
ALTER TABLE alter_ids ALTER id ADD GENERATED ALWAYS AS IDENTITY(START 10);
INSERT INTO alter_ids DEFAULT VALUES;
ALTER TABLE alter_ids ALTER id SET GENERATED BY DEFAULT SET INCREMENT BY 2 RESTART WITH 20;
INSERT INTO alter_ids DEFAULT VALUES;
ALTER TABLE alter_ids ALTER id DROP IDENTITY;
SELECT id FROM alter_ids ORDER BY id;
```

Returns 8, 10 and 20; DROP preserves the values and NOT NULL. For ON CONFLICT and MERGE:

```sql
CREATE TABLE override_paths(id INT GENERATED ALWAYS AS IDENTITY,k INT UNIQUE);
INSERT INTO override_paths(k) VALUES(1);
INSERT INTO override_paths OVERRIDING USER VALUE VALUES(99,1)
ON CONFLICT(k) DO UPDATE SET id=DEFAULT;
MERGE INTO override_paths USING (SELECT 2 AS k) s ON override_paths.k=s.k
WHEN NOT MATCHED THEN INSERT(id,k) OVERRIDING USER VALUE VALUES(999,s.k);
SELECT id,k FROM override_paths ORDER BY k;
```

Returns `(3,1)`, `(4,2)`: the conflicting proposal consumed 2 and its DEFAULT update consumed 3.
For new-column backfill:

```sql
CREATE TABLE populated(k INT);
INSERT INTO populated VALUES(1),(2),(3);
ALTER TABLE populated ADD id BIGINT GENERATED BY DEFAULT AS IDENTITY(START 10 INCREMENT 2);
SELECT id FROM populated ORDER BY id;
```

Returns 10, 12 and 14. Assignment to particular old rows follows physical scan order.
